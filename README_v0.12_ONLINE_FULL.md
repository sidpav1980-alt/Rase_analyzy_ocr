# Trail Race Analyzer v0.08 ONLINE FULL

Полное описание изменений, накопленных к версии v0.08.

## Общая структура
- Вкладки:
  1. Трасса
  2. ChatGPT
  3. Прогноз
  4. Итог
- Раздел «Лучшая тренировка» удалён из онлайн-версии.
- Внизу приложения сохранена подпись `Sidorenko Pavel (c) 2026`.

## Трасса / GPX
- Загрузка и обработка GPX трассы.
- Вывод дистанции, набора и сброса.
- Фактическое время прохождения берётся из временных меток GPX.
- Показываются:
  - без пауз;
  - с паузами;
  - темп.
- Если в GPX нет данных высоты:
  - выводится явное предупреждение;
  - набор/сброс показываются как «нет данных»;
  - профиль высоты пишет «В GPX нет данных высоты».
- Поле «Базовый темп» переименовано в «Рассчитать время для темпа».

## Анализ карты / OSM
- Анализ покрытия маршрута по OSM.
- Показываются:
  - классифицированная доля;
  - болото;
  - вода;
  - тропа;
  - грунт;
  - асфальт.
- Текст «Описание покрытия» удалён.
- Анализ карты очищается при обновлении страницы.
- Среднее ожидаемое время анализа карты — 15 секунд.
- Если анализ длится более 15 секунд:
  - запрос прерывается;
  - выводится ошибка «Анализ карты занял больше 15 секунд. Повторите снова.».
- Внешние запросы к Overpass ограничены по времени, чтобы не зависали.

## Броды
- Броды определяются по пересечениям GPX с водными объектами OSM.
- Пересечение по мосту не считается бродом и отображается отдельно.
- Водотоки с известной шириной менее 1 м не считаются бродами.
- Близкие повторные пересечения одного водного участка объединяются.
- Группировка идёт в пределах 500 м от первой точки группы.
- Для одного брода показывается только начальная точка.
- Пример:
  - `6.3, 6.5, 6.7` → один брод, отображается `6.3 км`;
  - `7.1, 7.2` → один брод, отображается `7.1 км`;
  - `16.0, 16.1` → один брод, отображается `16.0 км`.
- Количество бродов считается по сгруппированным начальным точкам.

- Во вкладке сохранена загрузка стартового списка XLSX / CSV.
- Сохранён AI-анализ стартового списка.
- Поле OpenRouter удалено.

- Прогноз места поддерживает Top-3, Top-10, Top-30 и Top-50.
- Если данных для итогового прогноза нет, прогноз финиша не заполняется.

## Прогноз по трём GPX
Для общего прогноза используются три отдельных эталонных GPX:

1. **Силовая трейловая GPX**
   - большой набор;
   - крутые подъёмы;
   - используется для зависимости скорость ↔ уклон.

2. **Быстрая трейловая GPX**
   - быстрое устойчивое трейловое усилие;
   - используется для оценки рабочей скорости на рельефе.

3. **Гоночная (плоская) GPX**
   - например, плоская 10 км;
   - задаёт базовый ровный темп и беговую экономичность.

Каждый файл загружается отдельно. Общий прогноз строится по:
- GPX трассы из вкладки «Трасса»;
- трём GPX-эталонам из вкладки «Прогноз».

## VO₂max и физиологические ограничения
- VO₂max вводится вручную.
- Для онлайн-прогноза VO₂max обязателен.
- Допустимый диапазон: 20–90 мл/кг/мин.
- VO₂max используется как аэробная поправка.
- Основные ограничители длинной гонки:
  - длительность;
  - пульс / LTHR, если доступны;
  - VO₂max;
  - накопленная усталость.
- Если HR/LTHR доступны, физиологическое ограничение считается по ним.
- Если HR/LTHR нет, используется VO₂max + расчётная длительность.
- «Расчётное время до закисления» — модельная оценка устойчивой интенсивности, а не прямое измерение лактата.

## Рекомендуемый темп
- В таблице прогноза показывается не максимальный, а **рекомендуемый темп**.
- За основу берётся средний прогнозный темп всей гонки.
- Подъёмы умеренно замедляют темп.
- Спуски ускоряют только немного.
- Первая треть дистанции идёт чуть спокойнее.
- Средняя треть — около среднего прогнозного темпа.
- Последняя треть — лишь немного быстрее, если рельеф позволяет.
- Все участки нормируются так, чтобы их суммарное время совпадало с общим прогнозом движения.
- Цель — избежать раскладки «очень быстро первые 20–25 км → 9–10 мин/км в конце».

## Кнопки прогноза
В разделе «Прогноз» две кнопки:
- `Рассчитать прогноз по трассе`;
- `Рассчитать прогноз по трассе с анализом GPX`.

Для второй кнопки:
- дополнительно используется анализ GPX / карты;
- каждый найденный брод добавляет `+40 секунд` к прогнозному времени;
- применяется та же цветовая логика состояний, что и у обычной кнопки:
  - серый — недоступно;
  - голубой — готово;
  - рабочий серый — расчёт;
  - зелёный — успех;
  - красный — ошибка.
- Между двумя кнопками добавлен визуальный отступ 14 px.

## v0.10 — штраф за тропы в прогнозе с анализом GPX
- Обычная кнопка «Рассчитать прогноз по трассе» не меняется.
- Кнопка «Рассчитать прогноз по трассе с анализом GPX» теперь дополнительно учитывает OSM-покрытие.
- Каждый сгруппированный брод: **+40 секунд**.
- Каждый фактический километр, классифицированный OSM как **тропа**: **+1:00 мин/км**.
- Штраф тропы распределяется по тем участкам таблицы, где OSM действительно классифицировал маршрут как `trail`.
- В статусе после расчёта показывается:
  - количество бродов и добавленное время;
  - километры тропы и добавленное время.
- Например, 14.1 км тропы добавят примерно +14:06 к прогнозу.


## v0.12 — грунт +30 сек/км и минимум 10 км для плоской GPX
- Для кнопки «Рассчитать прогноз по трассе с анализом GPX»:
  - каждый сгруппированный брод: **+40 сек**;
  - каждый километр OSM-тропы: **+60 сек/км**;
  - каждый километр OSM-грунта / gravel / dirt / earth / ground: **+30 сек/км**.
- Штрафы покрытия применяются только к фактически классифицированным OSM-участкам.
- Под кнопкой обновлено описание всех трёх поправок.
- В статусе результата отдельно показываются:
  - броды и их штраф;
  - километры тропы и штраф;
  - километры грунта и штраф.
- «Гоночная (плоская) GPX» теперь имеет обязательный минимум **10 км**.
- При загрузке плоской GPX короче 10 км файл отклоняется с ошибкой:
  `Гоночная (плоская) GPX должна быть не менее 10 км`.


## v0.12 — выбранный режим прогноза
После расчёта активный способ прогноза подсвечивается зелёным, второй доступный способ — синим. При переключении цвета меняются местами.
